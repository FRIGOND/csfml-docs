Tutoriel du **casse-briques** (CSFML 2.6), étape 6 sur 9. Cette page a une jumelle pour [CSFML 3.0](/3-0/tutorials/06-sprites/) : même plan, avec les différences d'API expliquées.

## Objectif

Remplacer les formes par des sprites. Les textures sont fabriquées par le programme lui-même : aucun fichier image n'est nécessaire.

## Prérequis

[Étape 5](/2-6/tutorials/05-collisions/) : le jeu avec collisions.

## Pas à pas

### Image, texture, sprite : qui fait quoi ?

- Un `sfImage` est un tableau de pixels **en mémoire** (le processeur). On peut lire et écrire ses pixels.
- Un `sfTexture` est une image **dans la carte graphique**. C'est ce que l'on dessine.
- Un `sfSprite` est un rectangle qui **affiche** une texture, avec une position, une couleur, une échelle…

Plusieurs sprites peuvent partager la **même** texture : nos 50 briques utilisent une seule texture.

### Fabriquer une image

[`sfImage_createFromColor`](/2-6/reference/graphics/image/#sfImage_createFromColor) crée une image d'une seule couleur ; [`sfImage_setPixel`](/2-6/reference/graphics/image/#sfImage_setPixel) change un pixel. Pour la balle, on crée une image transparente, puis on écrit en blanc les pixels qui sont dans un disque.

<Tabs syncKey="csfml-version">
  <TabItem label="CSFML 3.0">

```c
sfImage *image = sfImage_createFromColor((sfVector2u){size, size},
    sfTransparent);
```

  </TabItem>
  <TabItem label="CSFML 2.6">

```c
sfImage *image = sfImage_createFromColor(size, size, sfTransparent);
```

  </TabItem>
</Tabs>

<Tabs syncKey="csfml-version">
  <TabItem label="CSFML 3.0">

```c
sfImage_setPixel(image, (sfVector2u){x, y}, sfWhite);
```

  </TabItem>
  <TabItem label="CSFML 2.6">

```c
sfImage_setPixel(image, x, y, sfWhite);
```

  </TabItem>
</Tabs>

En 2.6, la taille et les coordonnées sont des arguments séparés.

### De l'image à la texture

[`sfTexture_createFromImage`](/2-6/reference/graphics/texture/#sfTexture_createFromImage) copie les pixels dans la carte graphique. Une fois la texture créée, l'image ne sert plus : on la détruit tout de suite avec [`sfImage_destroy`](/2-6/reference/graphics/image/#sfImage_destroy).

```c
texture = sfTexture_createFromImage(image, NULL);
sfImage_destroy(image);
```

### Créer un sprite

<Tabs syncKey="csfml-version">
  <TabItem label="CSFML 3.0">

```c
sfSprite *sprite = sfSprite_create(texture);

if (sprite != NULL)
    sfSprite_setColor(sprite, color);
return sprite;
```

  </TabItem>
  <TabItem label="CSFML 2.6">

```c
sfSprite *sprite = sfSprite_create();

if (sprite == NULL)
    return NULL;
sfSprite_setTexture(sprite, texture, sfTrue);
sfSprite_setColor(sprite, color);
return sprite;
```

  </TabItem>
</Tabs>

En 2.6, `sfSprite_create` ne prend rien : on donne la texture ensuite avec `sfSprite_setTexture`. Le dernier argument (`sfTrue`) remet le rectangle de texture à la taille de la texture.

[`sfSprite_setColor`](/2-6/reference/graphics/sprite/#sfSprite_setColor) **teinte** le sprite : la couleur est multipliée avec les pixels de la texture. Une texture blanche prend ainsi la couleur de sa ligne. La texture des briques est un dégradé de gris (plus sombre vers le bas) : multiplié par la couleur de la ligne, il donne du relief.

### Durée de vie : détruire dans le bon ordre

Un sprite **garde l'adresse** de sa texture (il ne la copie pas). Il faut donc détruire **les sprites avant les textures**. Voir [qui possède quoi](/guides/concepts/ownership/).

### Collisions et affichage

Le reste du jeu ne change presque pas : on remplace `sfRectangleShape_getGlobalBounds` par [`sfSprite_getGlobalBounds`](/2-6/reference/graphics/sprite/#sfSprite_getGlobalBounds), et le dessin se fait avec [`sfRenderWindow_drawSprite`](/2-6/reference/graphics/render-window/#sfRenderWindow_drawSprite). [`sfSprite_setOrigin`](/2-6/reference/graphics/sprite/#sfSprite_setOrigin) place l'origine de la balle en son centre, comme à l'étape 2.

La vérification du mode test relit la texture de la balle ([`sfTexture_copyToImage`](/2-6/reference/graphics/texture/#sfTexture_copyToImage)) : le pixel du centre doit être opaque et celui du coin transparent.

## Le programme complet

Ce programme compile avec `-std=c11 -Wall -Wextra -Werror -Wno-error=deprecated-declarations` (le header 2.6 `Event.h` est marqué « deprecated » : sans cette option, `-Werror` le transforme en erreur) et il est exécuté par les tests du dépôt.

```sh
make -C examples/tutorials/06-sprites CSFML=2.6 CSFML_PREFIX=system   # ou CSFML_PREFIX=$HOME/csfml-2.6
cd examples/tutorials/06-sprites && ./build/2.6/example
```

Pour compiler à la main, ajoute `-I examples/common` (le fichier `test_mode.h`) et lie : `-lcsfml-graphics -lcsfml-window -lcsfml-system -lm`.

## Ce que tu as appris

- La différence entre `sfImage`, `sfTexture` et `sfSprite`.
- Créer une image pixel par pixel, puis une texture.
- Teinter un sprite avec `sfSprite_setColor`.
- Détruire les sprites avant leurs textures.

## Erreurs fréquentes

- Détruire la texture alors que le sprite l'utilise encore (lecture invalide, repérée par valgrind). Voir [qui possède quoi](/guides/concepts/ownership/).
- Oublier `sfSprite_setTexture` en 2.6 : le sprite reste blanc (sans texture).
- Oublier de détruire l'image après `sfTexture_createFromImage` : fuite mémoire.
- Un sprite blanc ou invisible : voir [fenêtre noire](/guides/troubleshooting/black-window/).

## Exercices facultatifs

Il n'y a pas de corrigé : essaie, casse, recommence.

- Ajoute un petit reflet sur la raquette en changeant quelques pixels de son image.

- Fais clignoter la balle avec `sfSprite_setColor` toutes les secondes.
