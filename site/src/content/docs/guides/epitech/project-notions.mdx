Cette page ne contient **aucun code de projet noté**. Elle te dit quelles notions chercher et où les lire. Tu écris ton projet toi-même, en suivant ton sujet.
:::

Les noms de projets sont publics, mais les sujets ne le sont pas : les notions ci-dessous sont déduites de dépôts publics d'étudiants et de l'API (rapport `research/06` §4), et **ne remplacent pas ton sujet**.

## Bonnes habitudes (valables pour tous)

- **Charge une fois**, **détruis** à la fin, dans l'ordre inverse ([qui possède quoi](/guides/concepts/ownership/)).
- **Teste chaque `create`** avant de t'en servir ([plantages](/guides/troubleshooting/runtime-crashes/)).
- **Vide la file d'événements** avec un `while`.
- **Ne dépends pas du dossier courant** pour tes assets.
- **Sépare** en petites fonctions et regroupe l'état dans une `struct` ([coding style](/guides/epitech/coding-style/)).

## Fonctions autorisées

Chaque sujet liste les fonctions que tu as le droit d'utiliser. Cette doc **ne donne pas** cette liste : lis ton sujet. Les exemples de ce site utilisent parfois `printf`, `snprintf` ou `getenv` pour leurs tests ; ce n'est pas un modèle à copier dans un projet qui l'interdit.
