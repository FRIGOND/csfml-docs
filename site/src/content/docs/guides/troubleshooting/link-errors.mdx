Une erreur de **lien** arrive après la compilation : le compilateur a compris ton code, mais l'éditeur de liens ne trouve pas le code compilé d'une fonction.

## `undefined reference to 'sfClock_create'`

Message complet vu en test : `d.c:(.text+0xd): undefined reference to 'sfClock_create'` (en français : « référence indéfinie vers »).

**Trois causes possibles :**

1. **Un `-l` manque.** Chaque module a sa bibliothèque et aucune n'inclut les autres : `sfClock_*` est dans `-lcsfml-system`. Test n°5 : sans `-lcsfml-system`, erreur ; avec les trois libs, OK.
2. **Les `-l` sont avant tes sources.** Test n°6 : `gcc -lcsfml-system d.c` donne `undefined reference to 'sfClock_create'` (et `sfMilliseconds`). Mets les `-l` **à la fin**.
3. **Mauvais `-L`.** La lib n'est pas là où tu le dis.

**Solution** : `gcc -o app main.c -lcsfml-graphics -lcsfml-window -lcsfml-system` (+ `-lcsfml-audio`, `-lcsfml-network` si utilisés). La table « quelle fonction est dans quelle lib » est dans [compiler](/guides/install/compiling/).

**Vérifier** : `nm -D /usr/lib/x86_64-linux-gnu/libcsfml-system.so | grep sfClock_create` (chemin du paquet Ubuntu ; ajuste selon ta machine).

## `undefined reference to 'sin'` (ou `sqrt`, `cos`…)

**Cause** : les fonctions mathématiques sont dans `libm`. **Solution** : ajoute `-lm` à la fin. (Comportement standard de la libc ; non spécifique à CSFML.)

## `error while loading shared libraries: libcsfml-system.so.2.6: cannot open shared object file: No such file or directory`

Message exact vu en test, exit 127. Le programme **compile** mais ne **démarre** pas.

**Cause** : au lancement, le système cherche les `.so` dans ses dossiers standard. Ta bibliothèque est dans un préfixe personnel (build [depuis les sources](/guides/install/from-source/)), qu'il ne connaît pas.

**Solutions** (testées) :
- À la compilation : `-Wl,-rpath,<préfixe>/lib`. `readelf -d app | grep PATH` montre alors un `RUNPATH`.
- Ou au lancement : `LD_LIBRARY_PATH=<préfixe>/lib ./app` (exit 0).

**Vérifier** : `ldd ./app | grep csfml` doit montrer un chemin, pas « not found ».

## Le programme compile mais utilise la mauvaise version

`ldd ./app | grep csfml` montre `/usr/lib/x86_64-linux-gnu/libcsfml-system.so.3.0` alors que tu visais un préfixe local ? C'est que ni `-L` ni `-rpath` ne l'ont emporté (test réel : sans `-rpath`, la lib du système a été prise). Ajoute `-Wl,-rpath,<préfixe>/lib` et revérifie. Mélanger les headers d'une version et les libs d'une autre est une source de plantages mystérieux (voir [vérifier ton installation](/guides/install/check-your-setup/)).

:::caution[Non vérifié]
Un programme lié aux libs d'un préfixe avec `RUNPATH` charge-t-il bien les libs SFML de ce préfixe ? Oui avec notre recette (rpath `$ORIGIN` posé à la construction, `ldd` vérifié). Avec une SFML installée par un autre moyen, je ne l'ai pas testé.
:::
